根目录作为编排层串联「数据→构建→部署」闭环：`fetch_and_build.py` 调用 GitHub REST API v3 拉取 starred/search/following events，经 `known_categories.json` 映射与 `classify_new()` 关键词分类后，读取 `template.html` 用 `__DATA__`/`__CATS__`/`__LANGS__`/`__FAVS__`/`__TRENDING__`/`__FEED__`/`__UPDATED__` 等占位符注入 JSON 数据块生成 `index.html`；`.github/workflows/update.yml` 每天 UTC 01:00 在 GitHub Pages Runner 上执行该脚本并将产物推送到 `gh-pages` 分支；`api/refresh.js`（由 `vercel.json` 注册）暴露 POST 端点，通过 GitHub API 的 workflow_dispatch 触发同一 `update.yml`，实现从外部手动刷新数据源。三者共享同一份数据契约（`known_categories.json`、`trending_snapshot.json`、`descriptions_zh.json`），保证定时构建与手动触发的输出一致。
