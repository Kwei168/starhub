模块由两个文件构成：根级 vercel.json 将 api/refresh.js 注册为名为 starhub-refresh 的项目函数并设置 maxDuration=10；refresh.js 作为唯一入口导出默认 handler(req, res)，按顺序执行四层边界校验——CORS 白名单（仅允许 https://starhub-refresh.vercel.app 与 https://Kwei168.github.io）、OPTIONS 预检返回 204、非 POST 返回 405、来源不在白名单直接 403；随后校验 X-Refresh-Key 头是否匹配 REFRESH_KEY 环境变量，再检查 GH_TOKEN 是否存在，最后使用 Node 原生 fetch 调用 GitHub REST API v3 的 workflow_dispatch 端点（repos/Kwei168/starhub/actions/workflows/update.yml/dispatches，ref=main）并以 Bearer token + User-Agent: starhub-refresh 发起请求。依赖方向单向向外：仅依赖 Node 内置 fetch 与 Vercel 注入的环境变量，不引入任何第三方库；上游响应中 204 映射为 { ok: true }，其他状态码统一包装为 { error: 'GitHub API 调用失败' }，异常捕获以 502 返回 { error: '上游服务不可用' }，且刻意不向调用方回显 GitHub 错误细节以防信息泄露。
