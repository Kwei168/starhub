- 跨文件实体统一使用 GitHub 风格的 `owner/repo` 字符串或业务 `key` 作为关联主键，确保分类、描述、分析与榜单能按 key 对齐。
- 源列表类文件（`bestblogs_sources.json`、`t1_sources.json`、`t2_sources.json`）采用固定字段顺序（如 `key/name/cat/url/color/source` 或 `[key,name,avg]`），并按数值字段降序排列。
- 分析结果文件（`bestblogs_analysis.json`、`trending_snapshot.json`）将每个实体映射为一组预计算指标（如 total/dated/72h/7d/30d/daily_avg/newest/daily_30d 或热度分数），避免消费端重复计算。
- 面向前端的文案（如 `descriptions_zh.json`）保持单行中文摘要，便于直接嵌入 UI 卡片而不需二次处理。
