# Spec：RSS 聚合页默认排序缺陷修复（Phase 1）

日期：2026-09-14
状态：待确认

影响文件：`build_rss_aggregator.py`（唯一）

## 1. 问题陈述

默认页（`sortMode='newest'`）首屏被"无日期条目"占满，形成同源扎堆：

| 指标 | 实测值（11:37 线上构建，8553 条） |
|---|---|
| 可见前 120 条中无日期条目 | **120 / 120 = 100%** |
| 独立信源数 | **7** |
| 前 3 源占比 | **77.5%** |
| 无日期条目总量 | 201 条 = 全量的 **2.4%** |
| 跨代构建（相隔 3.1h）首屏重叠 | **95.8%**（内容冻结） |

## 2. 根因（已证实，非推断）

**D1 — 比较器语义在降序调用下反转（决定性）**
`_dateCmp(x,y)`（`:1999-2005`）的 NaN 分支 `if(isNaN(tx)) return 1;` 是为**升序**写的，注释声称"无日期沉底"（`:1997-1998`）。
但 `newest` 分支（`:2018`）以降序调用 `_dateCmp(b.date, a.date)` → 无日期条目被判为"更早" → **置顶**。
`active` 分支（`:2014-2015`）存在同一反转。

单元验证结果：`降序实际：无日期 → 最新 → 较旧`；`注释期望：最新 → 较旧 → 无日期`。完全相反。

**D2 — 刷新路径口径不一致（时区盲）**
`_mergeRemoteSources` 的 `:3041`、`:3043` 使用 `(b.date||'').localeCompare(a.date||'')` 字符串比较。
实测位移：`+08:00` 源平均前移 **172 位**，`Z` 源后退 **155 位**。

**D3 — 刷新路径在重排前提前返回，坏顺序被永久固化**
`:3040` `if(!added.length) return 0;` 使后面两行重排永不执行。页面构建与 `/api/rss` 同代时 `added=0`（实测）→ 5 分钟定时器空转 → 页面被钉死在 chunk 合并后的顺序。

**D4 — 无日期条目无法通过既有降级通道兜底**
`pub_date` 的值是 **JSON `null`**（非空串），`time_str=''`，`bad_date=false`。
`bad_date` 通道覆盖的是"日期不可信"，**不覆盖"日期缺失"**。

## 4. 验收标准（Phase 1）

以 `/api/rss` 实取载荷（8553 条）为固定输入，复刻 `buildArt()` → `applySort()`：

| 编号 | 断言 | 基线（修复前） | 目标 |
|---|---|---|---|
| A1 | 可见前 120 条中无日期条目数 | 120 | **0** |
| A2 | 无日期条目在全局序列中的首位置 | 第 1 位 | **≥ 8353**（全部退到尾部） |
| A3 | 独立信源数（前 120） | 7 | **≥ 18** |
| A4 | 首屏最新条目时间 | 无有效时间 | **≤ 1 小时前** |
| A5 | `_dateCmp`（升序，`oldest` 模式）行为 | 无日期沉底 | **不变**（回归保护） |
| A6 | 刷新路径在 `added=0` 时的行为 | 不排序 | **首屏无日期占比异常时触发规范化** |

A2/A3/A4 已在 `.deploy-tmp/_ablation2.txt` 用离线复刻验证（S1 行），A1/A5/A6 由新增测试守住。

## 5. 设计

**原则：不改变任何排序语义，只把"降序"这条路走对。**

新增一个**方向明确**的比较器，与现有 `_dateCmp` 并列：

```js
/* 时区安全降序比较：无日期一律沉底，与调用方向无关 */
function _dateCmpDesc(x,y){
  var tx=x?new Date(x).getTime():NaN, ty=y?new Date(y).getTime():NaN;
  if(isNaN(tx)&&isNaN(ty)) return 0;
  if(isNaN(tx)) return 1;      /* x 无日期 → x 靠后 */
  if(isNaN(ty)) return -1;
  if(tx===ty) return 0;
  return tx<ty?1:-1;           /* 新的在前 */
}
```

- `_dateCmp` **保持原样**，仅服务升序（`oldest`）。
- 三处降序调用改用它：`:2018`、`:2015`、`:2014`。
- `:3041` 改用它；`:3043` 改为调用 `applySort()`（DRY：不再维护第二套排序逻辑）。
- 改动 `:3040`：把"提前返回"拆成"有新增走增量合并 / 无新增走规范化校验"，规范化仅在检测到首屏被无日期条目污染时触发，健康状态零跳变。

**复杂度约束**：只新增 1 个函数 + 改 5 处调用点，预估净增 < 20 行。不引入配置项、不改数据格式、不改构建产物结构。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 无日期条目沉底后，用户翻到底部会看到 201 条静态页 | 这是**正确**行为（它们确实没有发布时间）。真正的治理是 P2-1，随 P1-1 排期。 |
| `_dateCmpDesc` 与 `_dateCmp` 逻辑重复 | 有意保留双份：两者语义相反，合并成带方向参数会让"方向"重新变成隐式契约，正是 D1 的成因。 |
| 刷新路径触发规范化造成可见跳变 | 触发条件为"首屏无日期条目占比 > 50%"，健康状态下不可能命中。 |
| 本地 `rss-aggregator.html`（08:28 构建）为旧版 | 改动只落在构建脚本；产物由 CI 重新生成。测试直接从构建脚本抽取 JS，不依赖本地产物。 |

### 已验证不成立的攻击路径（红队自述）

- `_dateCmpDesc` 非传递性 / NaN 环：构造 无日期 / 有效早 / 有效晚 三元组，满足弱序，无环。
- 全仓 `_dateCmp(` 调用点逐处核对，方向均正确（`:2020` 升序、`:2023` 求最大值）。
- `active` 模式混用升序 `_dateCmp` 求 `srcLatest` 最大 + 降序 `_dateCmpDesc` 排序，方向正确。
- newest/active/oldest 三模式纠错**收敛**（`_bad` 归零后不再触发），无抖动。
- 性能：8553 条 `applySort` ≈ 11 万次比较，5 分钟周期可忽略；首屏 `new Date()` 仅 `wallLimit` 次。
- 抽取式测试的失败模式均为"响亮失败"（锚点缺失 → 退出码 2；依赖缺失 → `ReferenceError`），无静默抽错内容。
