# RSS 日期获取修复（Phase 1b）

日期：2026-09-14 ｜ 状态：**已实现，测试全绿，未提交**

## 1. 方向修正（用户判定）

Phase 1（`2026-09-14-rss-default-sort-fix.md`）把无日期条目**沉底**。用户判定方向错误：

> 排序沉底这是不对的 方向不对 正确的是抓取真正的时间 然后排序
> 沉底的结果只能是永远不可见 除非用户主动搜寻

本轮据此改方向：**取回真实时间 → 按时间排序**。沉底从"主要手段"降级为"最后兜底"
（仅用于既无 pub_date 又无 first_seen 的条目；实测触发 0 次）。

## 2. 目标与非目标

目标：
1. 源侧能取到日期的，必须取到；
2. 确实取不到的，给一个**真实、可排序、语义明确标注**的降级键（first_seen = 我方首次收录时刻），不留空；
3. 排序口径在**所有**环节统一为绝对时间。

非目标（需单独立项）：
- 文章页面级日期抓取（本仓库目前没有页面抓取器，`full_content` 来自 feed 的 `content:encoded`）；
- 同源配额 / tierInterleave 改造（改变默认排序语义）；
- 源侧日期**时区误标**（超能网等，独立缺陷，见 §6）。

## 3. 归因（201 条无日期 / 12 个源，全部端到端重抓核实）

| 类别 | 条数 | 源 | 证据 |
|---|---|---|---|
| A 解析缺陷（源侧有日期，我们解析失败） | **75** | 小胡子哥 30、卢昌海 29、tinyprojects 16 | 逐条 dump 原始 XML：每一条都带 `pubDate`，`_parse_rss_date` 返回 None |
| B 源侧真无日期 | **99** | 知乎日报 34、Google Dev Blog 20、喷嚏网 17、美团 10、中国日报 5、BBC 5、CNN 4、财富中文网 4 | 枚举条目的**全部子元素 tag**，不存在任何日期元素 |
| C 上游滚出窗口 | **29** | 人民网 | 本次抓取 18/18 均带日期，历史那 29 条已不在 feed 窗口内 |

（75+99+29 = 203，与 201 的差为快照口径差）

A 类三种失败写法：
```
Fri Oct 27 2023 15:13:00 GMT+0800 (China Standard Time)   ← JS Date.toString()，月在前
13 Sep 2026 07:28:00 EST                                  ← 无星期前缀 + 字母时区
Mon, 18 May 2020                                          ← 仅日期
```
另发现一处此前无人察觉的**静默错 8 小时**：旧正则的时区组是 `([+-]\d{4})?`，
不匹配 `+08:00` 写法 → 时区被整段丢弃、当 UTC 处理。

## 4. 改动清单（`build_rss_aggregator.py`，单文件）

| # | 位置 | 内容 |
|---|---|---|
| 1 | `_RSS_DATE_RE` / `_rss_tz_offset` / `_parse_rss_date` | 覆盖上面三种词序与写法；字母时区表（RFC 822）；缺时区按 UTC |
| 2 | `_fallback_date_iso()`（新增） | 取不到 pub_date 时用 first_seen 生成 +08:00 的降级排序键 |
| 3 | `_accumulate_history()` 条目重组 | 写降级键 + `date_fallback` 标记（**只改副本，不污染历史**） |
| 4 | `_accumulate_history()` 过期分支 | 过期时若历史已有同链接条目 → 回写真实日期，让裁剪循环当场清掉（否则陈旧条目靠 first_seen 续命最多 72h） |
| 5 | `_save_api_snapshot()` | 透出 `date_fallback` |
| 6 | `_chrono_key()` + `_split_data_chunks()` | 切块选片改为**绝对时间**排序（原为字符串比较，时区盲 → 首屏选片会选错） |
| 7 | JS `buildArt()` / `_applyRemote()` | 传播 `dfb` 标记（两条数据通道都覆盖） |
| 8 | JS `_dynTimeCore()` + `_dynTime()` | 降级条目显示「收录 X」，不冒充发布时间 |

## 7. 遗留（未处理，需你决策）

1. **124 条的"真正发布时间"仍未取得**：其 feed 结构里根本没有日期元素。
   两条路：(a) 对无日期条目做**页面级日期抓取**（`article:published_time` / JSON-LD `datePublished` / `<time datetime>`），
   按 link 缓存进历史 → 一次抓取长期复用；(b) 把 4 个 anyfeeder 镜像源换回原生源。
2. **超能网等源的时区误标**：其 `pubDate` 把北京时间标成 `+00:00` → 解析后比 `first_seen` 晚约 6 小时
   （实测 43 条全部命中"日期倒挂"）→ 前端未来钳制把它改写成打开页面的时刻 → 6 条同刻挤在首屏最前。
   `bad_date` 审计已能识别（构建日志 7 个不可信源），但**只标记不校正**。
3. `pageerror: URIError`（每次加载一次，低优先级）。
4. 根目录 0 字节 `nul` 文件（Windows 保留设备名，常规途径删不掉）。
